## 1. 问题

输入 `lianzhengtixing`（廉政提醒），首选整句为「李安整体性」。

用户诉求经澄清后收窄为：**不要让「李安」这种低频专名过于轻易地占据 `lian` 这个音**，而非要求「廉政提醒」上首位。

## 2. 根因

两个设计叠加，产生了一个**结构上不该存在的状态**。

### 2.1 切分只保留一条路径

`Dag::maximum_match`（`wind-engine/src/pinyin/dag.rs:51`）是 DP 最大覆盖切分，回溯后返回单个 `Vec<String>`。

对 `lianzhengtixing`：位置 0 上 `match_at` 按长音节优先返回 `["lian","li"]`，`lian` 先写入 `dp[4]`；`li`+`an` 随后以相同覆盖长度到达位置 4，被 `dag.rs:72` 的严格大于判据 `covered > dp[end]` 丢弃。

**实测切分恒为 `["lian","zheng","ti","xing"]`，`li|an` 从不产生。**

### 2.2 词图查询不校验边界

`lattice.rs:190` 与 `:206`：

```rust
let code: String = syllables[start..end].join("");   // "lian"
let results = dict.search(&code);                     // 裸 search，不带边界
```

词库中「李安」的编码是 `li an`（两个音节），存储时拍平为 `lian`，边界另存于 `DictEntry::boundary`（`wind-dict/src/binformat.rs:99`）。`search` 不校验该字段，于是「李安」从单音节边 `lian` 上被返回。

### 2.3 畸形状态与打分放大

结果是词图里出现一个 **2 个汉字只占 1 个音节跨度** 的节点：

```
李安  start=0 end=4  syls=["lian"]  log_prob=-11.0656
```

`score_node`（`lattice.rs:117`）的长词加成按**汉字数**计：

```rust
log_prob += BASE_CONTENT_WORD_BONUS * (char_count as f64).sqrt() * freq_factor;
```

「李安」用 1 个音节换 2 个字，白拿 `+1.03` 加成，以 0.30 分之差压过高频单字「连」（`-11.3698`），进而使整句「李安整体性」(-22.3249) 险胜「廉政提醒」(-23.1961)。

**实测同类畸形词条共 1110 条，其中 1107 条被 unigram 收录**（即绝大多数真的会拿到加成）。它们有共同结构：后字为零声母字（安/额/鹅/爱/奥/岸/昂），与前字连写后被最大匹配吞成单音节 —— `xi+an→xian`、`qi+e→qie`、`yu+e→yue`、`gu+ai→guai`。

## 3. 已否决的方案

**「字数 ≠ 音节跨度则不发长词加成」** —— 已实测，否决。

- 目标达成：「李安」在 `lian` 格从第 1 掉到第 2
- 但代价不可接受：`qietubiao` 从「企鹅图表」变成「且图表」，`liandaoyan` 从「李安导演」变成「连导演」
- 根本缺陷：该规则**完全不看词频**，「李安」（低频人名）与「企鹅」（高频常用词）在判据下是同一类东西，只能一视同仁地把 1110 个词全部降权

**教训**：这是在下游给一个上游造成的畸形状态打补丁。方向不错（与 librime 同向），但地基不对、力度不足，卡在「谁也没赢」的中间地带。

## 4. librime 对照

| 维度 | librime | 我们 |
|---|---|---|
| 切分 | 保留全部路径的图（`EdgeMap = start→end→{音节集}`） | DP 只留一条 |
| 消歧时机 | 延后到打分，用 credibility 软罚 | 提前在切分，硬丢弃 |
| 词典键 | `class Code : public vector<SyllableId>` | 扁平串 + 旁路 boundary（查询不校验） |
| 边界正确性 | 机制保证，假阳性不可能 | 查询绕过 → 假阳性 |
| 长度偏好 | 每词固定罚 `-18.42`（按**词数**） | `+3.0*sqrt(汉字数)`（按**字数**） |
| 歧义音节 | `CheckOverlappedSpellings` 罚 `-23.03` | 无对应机制 |
| 单字/虚词特判 | 无 | `-3.0` / `+2.0` 硬编码 |

关键源码：
- `ref/weasel/librime/src/rime/algo/syllabifier.cc:75-137`（建图保留全路径）、`:243-276`（歧义音节罚）
- `ref/weasel/librime/src/rime/dict/vocabulary.h:21`（Code 定义）
- `ref/weasel/librime/src/rime/gear/grammar.h:18-26`（每词固定罚）

librime 对「李安」的压制是**两道软惩罚叠加**（歧义音节 `-23.03` + 多一个词 `-18.42`，合计约 `-41.4`），并以隔音符号作为用户主动消歧的出口 —— 隔音符号会让长边在 prism 里根本匹配不上（`syllabifier.cc:80-84`），而非「标记边界」。

**注意**：该机制对「李安」和「西安」是一视同仁重罚的。这是一套产品语义（缩合音词不打隔音符号就压制），不是单纯的打分技巧。

### 4.1 真实 Rime 行为实测（用户提供，2026-07-21）

在 Rime 中以两种拼音方案测试：**输入 `xian` / `qie` 时，「西安」「企鹅」排在单字之后，约第 4/5 位。**

对照我们当前的行为：`xian` 的「西安」第 3 位（w=6091），`lian` 的「李安」第 5 位（w=1361）。

**结论：两边的候选层已经很接近，差距不在候选层。** librime 那个 `-23.03` 歧义罚的可观测效果主要落在**整句/词组合成**上 —— 缩合音词在候选列表里依然处于第 4/5 位这种完全可用的位置，并未被赶出列表。

这与 B（边界感知词图）单独实施的形态一致：B 只影响词图/整句合成，候选路径原封不动。

**因此 Phase 4 的歧义音节罚很可能不必要**，待 Phase 1/2 数据确认。若 B 落地后整句层面的行为已与 Rime 相当，则不引入 `-23` 罚 —— 不为一个已解决的问题增加机制。

## 5. 关键发现：不需要改二进制格式

librime 的 `Code = vector<SyllableId>` 形态**不应照搬**，原因有二：

1. **wdat v4 的边界数据已经足够。** `DictEntry::boundary: u64`（`binformat.rs:94-99`）存的是 code 中各音节起始字节位的 bitmask，与音节切分**一一对应、无损**（音节长度 = 相邻起始位之差），唯一限制是 code ≤ 64 字节。真值来自 rime 源数据 `你好\tni hao` 中的空格。

2. **`wind-dict` 是码表引擎共用的。** 码表编码是五笔字根串，无音节语义。全仓 `search*` 调用点 114 处，拼音专属的只有十几处。librime 没有码表引擎共用同一个 trie，我们有。

**这个判断在仓库里已有先例。** `d096846` 的作者留了字条（`wind-dict/src/cached.rs:167-170`）：

> 边界只对拼音有意义，而 `search` 的消费方遍布码表/英文/cmdbar/composite 等无音节概念的场景，不应被拼音的需求污染接口。仅拼音引擎改用本方法。

**且 `search_with_boundary` 这个 API 已经存在**（`cached.rs:218`，返回带 `boundary` 的 `DictHit`），`search_prefix_with_boundary` 也在（`:239`）。基础设施是齐的，缺的只是 `lattice.rs` 去用它。

### 5.1 这是一次已知漏洞模式的复发

`684999e`（双拼真值校验）的提交信息记录过：P2a 漏了一处 —— 拼音引擎直接持有 `CachedDict` 而不经 `SystemDictLayer`，所以 `lookup_with_fuzzy` 仍在用 `search()`，修复前看到的全是 0 边界、等于没设防。

**同一个漏洞现在原样存在于 `lattice.rs`。** 这不是新问题，是同类问题的第二次发作。

## 6. 三根柱子

| | 内容 | 单独实施的后果 |
|---|---|---|
| **A** 多路径切分 | 切分图取代单一路径 | 扁平键仍让「李安」**同时**从 `lian` 单音节边被捞到 → 重复计入，比现状更乱 |
| **B** 边界感知查询 | `lattice.rs` 改用 `search_with_boundary` + 校验 | 见 6.1，代价比预期小得多，但有一类真实伤亡 |
| **C** 打分调整 | 按词数固定罚取代按字数加成；歧义音节罚 | 依赖 A/B 才有意义 |

### 6.1 对 B 单独实施的重新评估

初判「B 单独实施会让『西安』打不出来」**是错的**，混淆了两条独立路径：

- **词图路径**（受 B 影响）：只用于 Viterbi 整句合成
- **候选路径**（不受 B 影响）：`dict.search` 直接产出的普通候选

实测佐证：`convert("xian",10)` 中「西安」位列第 3（w=6091），来自候选路径；且单音节输入根本不跑 Viterbi（需 `syllables.len() >= 2`）。因此 B 单独实施后，「西安」「李安」**仍是可选候选，只是不再参与整句合成** —— 这正是期望的行为。

**但 B 单独实施确有一类真实伤亡：跨多音节且内含缩合音的词。**

以 `xianjiaotongdaxue` 为例：「西安交通大学」的真实边界是 `xi|an|jiao|tong|da|xue`（6 音节），而当前切分给出 5 个音节。边界校验会判定不匹配 → 该词被逐出词图 → **打不出来**。它 5 个音节未超 `max_word_len=10`，走的是词图而非 step 1.5 兜底，无法被兜住。

**这正是 A 存在的理由**：多路径切分下，图中会保留 `xi|an|jiao|tong|da|xue` 这条路径，该词以真实的 6 音节跨度合法匹配。

### 6.2 核心问题与 Phase 0 的实测修正

原问题：1110 条畸形词条中，有多少只需 B 即可修复，有多少必须付 A 的代价？

**Phase 0 实测已给出分布，且推翻了本文档此前的刻画。**

本文档第 2.3 节曾把 1110 条整体描述成「李安」那一族（`xi+an→xian` 式两字缩合）。实测分布（判据见 `tests/pinyin_eval.rs`，入池前置：纯 CJK、2~8 字、汉字数 == 真值音节数、`mm` 完整覆盖 input）：

| 类别 | 判据 | 实测条数 | 语义 |
|---|---|---|---|
| **B** | `mm != true` 且 `mm.len() == 1` | **81** | 整词塌缩进**单个**音节边（李安/币安/巨额）—— 即「N 字占 1 音节跨度」的畸形节点本身 |
| **C** | `mm != true` 且 `mm.len() >= 2` | **1021** | 跨多音节、内部某处边界不符（长安大道/险恶环境/李奥瑞克） |

**「李安」那一族只有 81 条，占 7.4%；92.6% 是多音节词，即必须靠 A 才能救的那一类。**

此外实测发现本文档此前完全未计入的一批：**另有 3347 条「音节数相同但切法不同」**（`暗暗` 真值 `an|an` vs 切分 `a|nan`；`爱党爱国` 真值 `ai|dang|ai|guo` vs 切分 `ai|dan|gai|guo`）。这批同样过不了边界校验。

**C 类总计 4362 条 —— Phase 2 的伤亡面比原估计大四倍。**

判据说明：采用 `mm.len()` 而非「是否含零声母字」，因为前者直接刻画**缺陷的结构形态**（「占据单音节边」才是"短词被误提升"的机制），后者只是该形态的常见成因。

**注意**：分布 ≠ 归因。上表说明的是「有多少词的边界与切分不符」，尚未说明「B 单独实施后各类的命中率实际掉多少」。后者由 Phase 1 实测回答。

#### ⚠️ 读数陷阱（必读，否则 Phase 1/2 结果必被误读）

1. **B 类 top-1 恒约等于 0，是判据的必然结果，不是缺陷。** B 类输入串恒为单音节（`bian`/`lian`/`jue`），首选必然是高频单字（便/连/绝）。**B 类唯一有信息量的指标是 top-5 与 MRR。**

2. **~~Phase 2 之后 B 类指标「变差」是修复生效的证据~~ —— 此条已被 Phase 1 实测证伪，见下。**

   **订正**：B 类指标对边界校验**结构性不敏感，delta 恒为 0**。原因：B 类输入按判据恒为单音节，而 `mod.rs:741` 把整个词图逻辑闸在 `syllables.len() >= 2` 之后 —— **B 类输入根本到不了词图代码**。

   原判断是从机制推的（B 类词不该进词图），推理本身没错，错在未检查这类输入是否真的会执行到那段代码。**若不知此事，看到「B 类 delta 全 0」会误判为「修复没生效」，进而回头去改一个本来正确的实现。**

   B 类的真实效果体现在**含 B 词作为子跨度的更长输入**上（如 `lianfenxi`、`lianzhengtixing`），须用定点探针观察，不能靠 B 类聚合指标。

   仍然成立的部分：**B 类聚合指标不可用作门禁** —— 但原因是它不敏感，而非它应当变差。

3. **A 与 C 的绝对值不可横向比较。** C 类 top-1（87.2%）高于 A（77.0%），因 C 类词平均更长、同音竞争者少；A 类混入大量二字词、同音噪声重（如 `ziji` 期望「自激」而首选「自己」）。**只能各自纵向比 delta。**

已知观察点（Phase 2 的直接验证靶）：`lianfenxi` 期望「链分析」实得「李安分析」；`shifoulian` 期望「是否立案」实得「是否李安」。

### Phase 3 已完成（2026-07-21）— 附一条关键架构理解

实现要点：未做任何路径枚举。音节是连续子串，故 `syllables[start..end].join("")` 恒等于 `input[p..q]` —— **词典查询由字节区间唯一决定，最多 O(n²) 个区间，与路径数无关**；「该词能否由合法切分到达」则反过来拿词条自身 `boundary` 当候选路径去图上验证（`SegGraph::mask_path`）。**路径爆炸结构上不可能发生，无需剪枝。**

路径规模普查（20 万条真实编码）：43.75% 的输入仅 1 条路径，最坏真实输入 `miaomiaomiaomiaomiaomiao` 为 729 条。词典查询 7.13 → 15.91 次/转换（2.23x），折合约 0.41ms → 0.81ms 每次转换。

#### ⚠️ 关键理解：`maximum_match` 本身就是一个隐式的歧义音节惩罚

其 tie-break（`match_at` 长音节优先 + `covered > dp[end]` 严格大于）**永远偏好更少更长的音节**。多路径移除了这个隐式偏置，而没有任何东西补上 —— 于是 `score_node` 的真实性质暴露出来：**它对「多加一个词」和「多加一个音节」都不收费**，把低频词打碎成两个高频片段在原始 log_prob 上就是赢的。

librime 的 `CheckOverlappedSpellings`（`-23.03`）正是同一偏置的显式版本。

**因此 Phase 4 不是打磨，而是把旧架构靠巧合获得的偏置用显式形式重建回来。** 这与「是否引入 librime 的产品语义」是两回事 —— 我们本来就有这个偏置，只是从未被写出来、也就无从调节。

#### 实测（N=4000，切分失败数）

| | 修 B 前 | Phase 3 | delta |
|---|---|---|---|
| C 类 wrong_split | 405 | 325 | **−80 修好** |
| A 类 wrong_split | 1 | 13 | **+12 弄坏** |

同一机制的两面，6.7:1 有利。A 类新增的 13 条**全部是同一根因、零例外**：音节被拆成两个且后半为零声母字（an/e/ao/ang/a/ai）—— `guotian` 过天→过提案(`guo|ti|an`)、`yexian` 掖县→也西安(`ye|xi|an`)、`hualong` 化龙→和阿龙(`hu|a|long`)。与 C 类缩合音是同一族。

比率稳定（N=1000 时 0.30%，N=4000 时 0.325%），非抽样噪声。

A 类 top-1 几乎不动（78.53% → 78.45%，−0.08pp），因这 13 条大多本就不在 top-1（掖县 w=8、过天 w=2 打不过 30M 基数整句）。**但它现在会出现在预编辑区** —— preedit 跟随首选，用户将看到 `ye'xi'an`、`guo'ti'an`、`hu'a'long`。

#### 两边残余是同一记分缺陷的相反方向

- C 的残余 325 条：正确路径已可用，但记分器**仍偏好 mm**
- A 的新增 13 条：记分器偏好了**不该选的非 mm 路径**

均为「路径长度免费」。

#### ⚠️ 一条被推翻的结论（记录以免重犯）

Phase 3 初次报告曾称残余 C 类漏网「绝大多数是切分正确的同音词竞争」。**实测证伪**：135 条漏网中仅 52 条（38.5%）切分正确，83 条（61.5%）仍是切分失败。

成因：从混合了两类的 dump 中挑出符合论点的例子做模式匹配，**在计算指标之前就先说出了结论**。seg-accuracy 指标本身是正确的工具，错在未经验算即断言其结论。

**教训：事后新增、且由提出者自行解读的指标，不可替代验算。**

### Phase 4 — C：打分调整

**Phase 3 后，本阶段已从「可选打磨」变为「必需」** —— 多路径移除了 `maximum_match` 的隐式歧义惩罚，必须以显式形式补回（见 Phase 3 小节的关键理解）。

#### 两个杠杆都需要，不是二选一（Phase 3 实测推导）

| 杠杆 | 能解决 | 不能解决 |
|---|---|---|
| **按词数固定罚**（librime `kPenalty = -18.42`） | A 类 13 条中约 11 条（错误路径词数更多） | `buhaojie`、`jiaguan` —— 词数相同、音节数更多 |
| **音节级 / 歧义音节罚**（librime `-23.03`） | 上述两条；以及 `lianzhengtixing` | — |

`lianzhengtixing` 是决定性的例子：「李安+整体性」与「廉政+提醒」**都是 2 个词**，按词数的罚对它们完全无法区分；两者的差别在音节数（5 vs 4）。

#### 其余待评估项

- 长度偏好从 `+3.0*sqrt(汉字数)` 改为按词数/音节数 —— 现行公式是 A 类 13 条破坏的放大器（碎片常额外收获实词加成）
- `LOG_PROB_MIN = -15.0` 的 clamp 悬崖（`lattice.rs:116`）：低于下限的词加成整个归零，「廉政」(-15.4175) 即因此一分未得。悬崖是否改为平滑衰减
- **是否采纳「隔音符号作为出口」这套产品语义** —— §4.1 用户实测显示 Rime 中缩合音词仍在第 4/5 位（候选层），差距主要在整句层。**倾向不引入额外的产品语义变更**，只做「补回隐式偏置」这一件事

#### Phase 4 已完成（2026-07-21）

实现：`SegGraph::ambiguous`（`dag.rs`）照搬 librime `CheckOverlappedSpellings` 的判据 —— 若 `p→j`、`j→q`、`p→q` 三条边同时成立（整段 Z 又能拆成 Y+X），则 j 是歧义接缝，**标记后半段** `j→q`（与 librime 一致，罚打给后半短边）。`lattice.rs` 两个常量：

- `WORD_PENALTY = 3.0` —— 施于 `score_node` 末尾。Viterbi 路径分是各节点之和，故「每节点减 W」等价于「按路径词数罚 k·W」（**⚠️ 施加条件已被 `9168d34` 修订：单字虚词豁免此罚，见 §12.1**）
- `AMBIGUOUS_PENALTY = 0.35` —— 按节点所跨切分中处于歧义接缝的音节数计罚

模糊命中同样计歧义罚：**惩罚是「切分」的属性，与词条来源无关**。

**取值与 librime 的偏离已核实**：两边**同为自然对数概率、量纲一致**（先前「量纲不同」的推测已被证伪）。差异来自机制 —— librime 的 `kPenalty = -18.42` 是**无语言模型时的兜底值**，有 grammar 时整个被替换；我们始终有 unigram，且 `score_node` 另有单字罚 −3.0、实词加成等项同时作用。

|---|---|---|---|
| A 类 top-1 | 78.53% | 78.45% | **84.33%** |
| A 类 wrong_split | 1 | 13 | **1** |
| C 类 top-1 | 87.20% | 86.55% | **90.77%** |
| C 类 wrong_split | 405 | 325 | **247** |

**四项全面优于此前任何阶段。**

|---|---|---|---|---|

#### ⚠️ 不可兼顾的取舍（结构性，非调参不足）

实测扫描确认：

- `AMBIGUOUS_PENALTY ≤ 0.30` → `lianzhengtixing` 退回「李安整体性」（本次改造的原始缺陷）
- `≥ 0.35` → `liandaoyan` 劣化为「连导演」
- **中间不存在兼顾值**；且 **0.30 与 0.35 的聚合指标完全相同**，差异仅在这两个定点

原因：两者是**同一个词、同一条 `li|an` 拆分、同一个歧义接缝**，切分层没有任何可区分二者的信息。真正的区分需要 **bigram 上下文**（「李安‖导演」vs「李安‖整体性」）—— `lm.rs:327-337` 已实现 bigram 插值，**缺的是磁盘语料**。这是后续独立立项的方向。

**用户已选择 0.35，优先修复原始缺陷。**

代价的确切形态：「李安导演」不是词典词条，只能作为 Viterbi 整句出现；整句既已判给「连导演」，它就**完全不在候选列表中**，而非仅被降权。**可接受的前提是隔音符号仍是确定的出口** —— 实测 `li'andaoyan` → 「李安导演」，已写入回归测试。

此取舍由 `tests/pinyin_ambiguity_penalty.rs` 守卫。**该文件存在的理由**：0.35 是刀刃值，而 `pinyin_eval` 的聚合指标看不出这条边被越过，只有定点能。改系数前必须先跑它。

现改为：**单字虚词（`is_function_word`）豁免该罚**。

起因：`cangmangdetianyashiwodeai` 首选出「苍茫的填鸭式我的爱」。用真实 unigram 拆解
`tianyashi` 跨度：填鸭式（1 词）路径分 −16.970 vs 天涯+是（2 词）−19.847，**差距 2.877
全部来自多付的那一次 `WORD_PENALTY`**，而基础分差本是 **−0.123（天涯是本该赢）**。

根因是 unigram 独立性：`P(天涯)·P(是)` 各含一份 `ln(total)`，双重扣分，于是低频三字整词
（填鸭式 w=152）压过二词正解。

**⚠️ 降 `WORD_PENALTY` 数值救不了**：要降到约 0.12 才翻，等于废掉这个杠杆，而 `6720abf`
的长专名保护会立刻复发。豁免虚词才是对症的 —— 虚词随内容词是语法黏着，不是「投机拆分
出来的碎片」，而 `WORD_PENALTY` 的本意只罚后者。这是对 unigram 独立性缺陷的近似补偿，
真解仍是 bigram（`lm.rs` 的 `SimpleBigramModel` 已实现插值，缺磁盘语料 —— 与 Phase 4
§「不可兼顾的取舍」指向同一个缺口）。

验证：`pinyin_eval` A/B/C 三类 top-1 / top-5 / 切分正确率**全不变**（仅 MRR <0.001 微调），
`pinyin_ambiguity_penalty.rs` 的 4 个定点未破 —— 即 **`AMBIGUOUS_PENALTY = 0.35` 那个刀刃
值在本次改动后仍然成立**。

### 12.2 `32085c4` 模糊音退出层级键，改权重惩罚

`cmp_match_layers` 的首要键原为 `is_fuzzy`，等价于「惩罚 = ∞」：真实词库下 `si` 的模糊
命中「是」被 230 条非模糊候选压到**第 231 位**，而生产候选上限是 50~300 —— 模糊音在
拼音 / 混输 / 临拼三条路径上全部等价于未实现。

现改为：`is_fuzzy` 退出层级键（首要键换成新增的 `is_abbrev`，承接原先被 `is_fuzzy` 借位
沉底的用户词简拼），模糊惩罚由引擎在 weight 上施加（`FUZZY_WEIGHT_SCALE = 0.01`）。

**与本文 §4 的 librime 对照同向**：librime 在 speller/algebra 拼写代数层做模糊音，`si`
直接变换成合法拼写 `shi`，产生的候选与精确候选天然混排、连惩罚都没有。Go 版
`ranker.go` 也只是 `score -= 100`（与音节对齐 +500 同量纲）—— Rust 移植时把连续分惩罚
错做成了布尔层级键。

同轮还修了非首音节模糊（`lattice.rs` 曾对多音节拼接串整体求变体，声母规则 `starts_with`
只能改首音节）：改为逐音节笛卡尔积，收口到 `FuzzyMatcher::expand_syllables`。

本文 Phase 2 关于「模糊变体路径刻意置 `boundary = 0`」的注意事项**不受影响，仍然成立**。

### 12.3 `c50b215` step 6.5：整句解让位于精确整词（降级而非销毁）

`lianzhengtixing` 下用户把「廉政提醒」加进词库并配高权重也换不回首选：整句「连整体性」
靠 `SENTENCE_WEIGHT_BASE`(3e7) 恒占第一，加上 `freq_rerank` 对 `is_sentence` 的无条件
锚定（该比较器不看 weight），**实测权重顶到 2e9 也赢不过**。而拼音不支持候选调位
（`handle_candidate.rs` 显式禁用），用户没有任何手段表达「我要这个词优先」。

librime 的做法是「有精确整词就不构造整句」（`script_translator.cc:387-393`）—— 那是
**销毁**，引擎判断错时用户想选也选不到。本仓改为**降级**：整句仍在候选里，只排到精确
整词之后，代价降为「多按一次」。

实现分两半，缺一则无效：引擎侧 weight 改为 `max(精确整词权重) − 1`（取相对值因为精确
整词权重量纲跨度极大，任何常数都会在某一侧翻车；取 max 而非 min 使整句位置可预期）；
`freq_rerank` 侧降级整句豁免顶部锚定（否则引擎的降权会被那个不看 weight 的比较器整个
顶回去）。新增 `Candidate::is_sentence_demoted` 而非清掉 `is_sentence` —— 后者是**来源**
属性，降级是**排序**决策。

数据：精确整词夺 top-1 92.20% → 99.70%；降级仅在 7.5% 的样本上触发。

### 12.4 step 6.6：整句解「有同码竞争者」时摘掉词频锚定（`is_sentence_contested`）

12.3 处理的是「合成整句该不该让位」，本节处理另一件事：**整句解自己就是一个词典精确
整词，而同码还有别的精确整词**。

`siyuan` 的「寺院」即如此 —— 它经 step 2 的**同文合并分支**继承整句身份（`existing.is_sentence
= true`），于是被 `freq_rerank` 的顶部锚定保护。而锚定是硬闸门（直接 `return Ordering::Less`，
衰减分连算都不算），**实测给「思源」灌到 `count=5000` 仍纹丝不动** —— 词频维度对整个
`siyuan` 编码失效。`gonghe` 共和/恭贺、`nihao` 你好/拟好、`sixiang` 思想/四项同构。

值得注意的是 **step 1.5 的注释早就写下了正确的判断**：

> 「整句解」应是引擎对整串输入的最优解读，不是"凡精确即整句"

step 1.5 用 `syllables.len() > max_word_len` 守住了这条线，但 step 2 的同文合并分支**无
条件**授予整句身份，等于从后门把"凡精确即整句"又放了进来，且覆盖面更大（任何音节数）。

修法：新增 `Candidate::is_sentence_contested`，在 step 6.5 之后标记「`is_sentence` 且未降级、
且存在另一个同码精确整词」的候选，`freq_rerank` 的锚定条件排除它。

- **判据与 6.5 的 `exact_max` 过滤器逐条一致**（同码、非模糊、不在补全/子短语层），差别
  只在这里要「存在性」而非「最大权重」。两处若不一致会出现「6.5 认为有竞争者而降级、
  6.6 认为没有而仍锚定」的自相矛盾状态
- **不动 weight**（区别于 6.5）：无词频记录时整句仍凭 `SENTENCE_WEIGHT_BASE` 量纲居首，
  本标记只让它在**有用户实际选择数据时**接受挑战
- 无竞争者的整句（`woshizhongguoren` 这类纯合成解、step 1.5 的超长词典整词）不置位、
  维持锚定 —— 那里没有「用户明确选过另一个同码词」这个事实可依据

**⚠️ 这是一次产品语义反转**：`pinyin_sentence_flag.rs` 原本断言「`gonghe` 首选恒为整句
「共和」，即便同码的「恭贺」有高词频」，该断言已按新语义改写为其反面。改回之前请先
确认要的是哪一种语义。

真实词库实测（标记正确性 + 行为）：

| 输入 | 整句 | contested | 灌 1 次词频后首选 | 无词频时首选 |
|---|---|---|---|---|
| `siyuan` | 寺院 | ✔ | 思源 | 寺院 |
| `gonghe` | 共和 | ✔ | 恭贺 | 共和 |
| `nihao` | 你好 | ✔ | 拟好 | 你好 |

### 12.5 `4c5474a` 用户词库权重对系统已有词生效

根因不是权重被覆盖，是**整条记录被丢弃**：step 6 合并用户/临时层时，若系统候选里已有
同文候选就 `continue`，用户词的 weight 从不参与任何比较。实测「自激」系统 w=18、用户
配 w=2,000,000,000，名次纹丝不动。

改为合并：weight 取 max（加词界面的用途是提权，没有理由把「用户填了个小数字」解释成
降权），**保留已有候选的 code 与 boundary**（`d4084b8` 踩过这个坑：合并时各字段各搬各的
会配出「A 层 code + B 层 boundary」）。

### 12.6 `e10933f` 用户长词打部分拼音即上浮

已入库的长用户词「清风输入法」打到 `qingfengshu` 不出，要打完整全拼才出现。根因是
`store_layer` 对前缀补全**无条件**标 `is_prefix = true`，而它在 `cmp_match_layers` 里排在
weight **之前** → 用户长词沉到所有首音节同音子短语（50~100+ 条）之下，权重再高也没用。

修法与本文的 `is_sentence_demoted` 同一手法：新增 `is_promoted_completion` 承接「已提升
进完整匹配层」这个**排序决策**，`is_prefix` 恒表「码更长」这个**结构事实**；
`cmp_match_layers` 改用「有效前缀层」= `is_prefix && !is_promoted_completion`。

### 12.7 这一族改动的共同形态

12.2 / 12.3 / 12.4 / 12.6 是同一个模式的四次发作：**一个布尔既表达「来源事实」又被当作
「排序层级键」使用**。而层级键 = 惩罚 ∞，任何数值维度（weight、词频衰减分）都翻不动它。

已经拆出来的排序决策字段：`is_sentence_demoted`、`is_sentence_contested`、
`is_promoted_completion`、`is_abbrev`。**要沉底或提升，就加自己的字段，别借现成的布尔。**
