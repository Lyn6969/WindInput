# 配置导入体系统一设计（入口矩阵 / 安全分层 / RPC 契约）

状态：设计定稿（2026-08 讨论产出）；P0-P2 已实施（片段管线 / 统一导入界面 / `.wpkg` 关联 / 协议 schema kind 官方域）。
2026-08-19 增补：Map 键逐条合并、config_patch 设置端两步编排、文本信封——权威描述均在
`docs/architecture/package-format.md` §2.2 / §2.3 / §2.4 / §3.3 / §3.4，本文不重复。
目标：让用户尽量不必手动编辑配置文件——预置内容通过片段与分发包到达，经统一管线安全应用。

## 1. 核心原则：入口可以多，通路只有一条

URL 协议、本地文件、`.wpkg` 双击、剪贴板、右键菜单——只是「内容怎么到达」的差异。
到达后一律汇入同一条管线：

```
到达（任意入口）
  → 内容侦测分派（package-format.md §4 的规则）
  → core 侧校验（REGISTRY / 穿越守卫 / 引擎类型…）
  → 只读预览确认（对话框内容最低要求见 package-format.md §5，任何入口不减配）
  → 应用（与 config.setItems 同路，运行时镜像即时回灌）
```

管线只实现一份；每新增一个入口，只加一小段「取内容」的代码。安全模型依赖这一点成立：
确认与校验在管线里，内容从哪来都绕不过去。

## 2. 入口矩阵

| 入口 | 承载内容 | 信任级别 / 门槛 | 状态 |
|---|---|---|---|
| `windinput://import/schema?url=…` | 分发包（官方托管） | 最紧：官方域白名单 + https + 强确认 | 协议框架已实现（wind-setting `protocol.rs`），schema kind 现为「暂不支持」占位，待接通 |
| 本地文件（统一导入界面选择 / 拖入） | 分发包 / `.toml` 片段文件 | 用户主动动作背书 + 强确认 | 新增 |
| `.wpkg` 双击关联 | 分发包 | 同本地文件；关联注册走 HKCU，复用协议的便携版不注册 / 取消不自愈 / 失效自愈规则 | 新增；argv 解析加 `.wpkg` 路径分支，单实例二次唤起转发已有 |
| 剪贴板 | 配置片段 | 最开放（片段只能改登记键，能力最弱 → 门最宽） | 新增 |
| 右键菜单「导入配置」 | 到达器，不承载内容 | 拉起设置进程直达导入对话框（`setting.open` 深链，页面 id 权威在 wind-setting 仓）；剪贴板由设置进程在对话框打开时读取 | 新增；菜单文案从严，不带括号补语 |

第三方分享的通路分工：官方内容走协议一键；第三方包走本地文件 / `.wpkg`（论坛下载后打开）；
第三方小配置走剪贴板片段（零托管成本）。协议收紧官方域不损失生态开放性。

## 3. UI 落点（wind-setting）

- **高级页**新增「导入与导出」独立组：`[导入文件…]` `[从剪贴板导入配置]`。备份还原卡片维持现状不动（备份页现有的「误选方案包 → 提示去方案页」重定向由统一分派器自然取代）。
- **桌面集成**卡片：新增 `.wpkg` 文件关联开关，与协议注册并排，同一套注册/自愈规则。
- **导入对话框 = 可编辑文本区 + 校验预览**（2026-08-19 真机反馈返工：初版只读列表看不到
  片段全文，已改多行文本区可就地修改）：

```
「导入配置」对话框
  [从剪贴板粘贴] [选择文件…]
  ─ 文本区（片段全文，可编辑，等宽字体）─
  [校验预览]
  ─ 预览区（只读列表）─
     ✓ ui.candidate.page_size        5 → 9
     ✗ input.foo.bar                 未知配置键
  [应用] [取消]
```

「应用」门控 = 校验通过 **且** 文本区内容与最后一次校验的原文逐字相同（一改动即失效，
杜绝「校验的是 A、应用的是 B」）。不做语法高亮等编辑器高级能力——文本区只是让片段全文
可见、小错可就地改，重编辑仍外包给用户的编辑器。

- **反向通路「复制为片段」**：把当前配置某段格式化成 TOML 写剪贴板（纯输出，无编辑器）。
  闭环 = 复制片段 → 外部编辑 → 剪贴板导入。expert 级配置键的 GUI 出口即此通路
  （文档站给带注释的片段模板，不为其做专属控件）。

## 4. 校验归属：core 出 RPC，设置仓只渲染

片段解析/校验收在主仓 core 侧（`config.previewPatch` / `config.applyPatch`，契约见
package-format.md §2.4）。理由：

1. REGISTRY 与「合法但不登记」白名单的权威在主仓；设置仓 capabilities 快照里复刻校验 = 第二份真相源，必漂移。
2. 包内 `config_patch.toml` 与剪贴板片段共用同一对 RPC，管线真正只有一份。
3. applyPatch 内部走 `config.setItems` 同路 → 校验、`set_user_value`（prune）、运行时镜像回灌全部继承，杜绝「设置了不生效、重启后生效」。

下载留在设置进程（沿用主题导入格局；core 侧 `theme.importFromUrl` 保持禁用）——core 不碰网络。

## 5. 明确不做的事

| 不做 | 理由 |
|---|---|
| 安装回执 / 已安装包列表 / 卸载 UI | 配置包导入即合并进用户目录，`set_user_value` + prune 后「装过的键」与「用户自改的键」存储上无区别，卸载语义不成立；撤销靠备份。方案包删除维持收集器反推（已知残留缺陷接受） |
| 应用内文本编辑器 | 设置 UI 架构做文本编辑成本高，且外部编辑器做得更好；见 §3 |
| 协议开放任意 https 域 | 当前收官方域白名单；第三方通路由本地文件与剪贴板承接 |
| extras 资源类型 | 悬置待定（首批候选：注释库），不阻塞其余任何一项 |
| 用户层 config.toml 拆分为片段目录 | 写入方向无法稳定（四个写入方收口在单文件的 `set_user_value`），片段是**导入/分发格式**，不是**存储格式**。若将来需要「装了可整体启停」，升级路径是只读 pack 层（L2 与 L3 之间），写入仍只落 L3 |

## 7. 已知兼容性事实

- 已发布旧版本遇到带 `config_patch.toml` 的包会把它当死文件落进 schemas 目录（不报错、不生效）。无法补救，分发侧标注最低应用版本（package-format.md §6）。
- 方案包 v2 无格式版本号且 `read_package_meta` 解析失败静默回落——这是 P0 要堵的洞本身。
